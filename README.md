# 知华·有据

**华为门店内容工作台 · AI+X 破界黑客松 / 华为产业落地赛道**

让导购从一句话开始，写出适合本店顾客的图文内容。项目围绕门店创作的三个问题设计：操作负担重、多店内容雷同、新品卖点容易失实。完整型号、产品事实、真实配图和使用条件贯穿创作与核查；门店的客群、顾客原问和体验安排用于形成不同表达。

## 使用流程

1. **说一句需求。** 输入产品、顾客和想发布的内容，点击“帮我准备图文”。规则归整入口识别已支持的完整型号、客群、场景和渠道；已具备必要信息时进入生成，型号有歧义时提供选项补齐。也可使用示例任务或展开详细设置。
2. **带上本店的表达。** 可选填门店类型、语气、周边场景、顾客原问和真实体验笔记，点击“保存门店设置”后在当前浏览器复用。这些输入用于创作方向，不作为产品性能、兼容性、价格或顾客评价的证据。
3. **查看图文和依据。** 系统按完整型号载入材料，依次完成事实提取、内容生成和独立语义核验。结果提供“图文成稿”“表达思路”“资料依据”“逐项核验”“客户方案”。引用事实保留原文、来源与型号，配图保留来源及位置。
4. **修改、复核、带走。** “微调文案”可直接编辑标题和正文；“核验并采用”使用本次事实重新核验，通过后建立新版本。复制与下载使用该新版本。页面可下载含正文、图片和来源的图文包，接口另支持 Markdown、JSON 和 HTML。

“生成三种门店版本”固定同一产品与发布平台，分别以校园、商务、社区门店的顾客问题组织内容，并逐条运行生成与核验。比较开头、事实侧重和行动引导；每个版本独立保留状态。重复表达提示使用最近同型号同平台结果的字符片段重合度，只用于提醒进一步调整，不作为原创性或营销效果评分。

九类业务场景：开学季、职场办公、内容创作、家庭换新、企业采购、门店到访、新品首发、节日营销、生态体验。

| 平台 | 内容策略 | 配图要求 |
|---|---|---|
| 小红书 | 口语标题、具体困扰、短段场景、话题标签 | 3-6 张 |
| 公众号 | 标题、导语、任务分段、解释与行动引导 | 2-4 张 |
| 门店朋友圈 | 一个场景、一个核心卖点、咨询引导 | 1-3 张 |
| 门店海报 | 主副标题、不超过 3 个卖点、行动引导 | 1 张 |

## 产品事实与生态体验

产品资料可来自指定共享库“任德耀新建华为PC知识库”，并支持同内容的个人 ima 知识库。已实际取回的资料与图片缓存用于应对接口额度或网络波动。每次结果记录 `source_mode`、原始取材时间和本次是否实时检索；缓存模式下，新任务仍重新调用模型生成与核验。

当前目录包含十款完整机型：MateBook 14 酷睿 Ultra、HUAWEI MateBook 14（鸿蒙版）、MateBook Pro、MateBook Pro S、MateBook Fold 非凡大师、MateBook D 14 2024、MateBook D 16 2024、MateBook D 16 SE 版 2024、MateBook GT 14、MateBook X Pro 酷睿 Ultra 微绒典藏版。以 `/api/catalog` 返回的完整名称为输入准则；支持目录不等于每款每种场景都已有实际生成记录。

`public_evidence.py` 对照华为官方公开规格、原文及图片文件 SHA-256。`ecosystem.py` 另按完整 PC 型号与功能主题选择六份官方支持资料，独立标记为 `official_huawei`。进入模型的生态材料为已读取的连续官方原文；说明性摘要只用于界面。原文、URL、适用机型、核验时间和使用条件保存在 `data/ecosystem_evidence.json`。

| 生态主题 | 两份华为官方来源 | 必须保留的条件示例 |
|---|---|---|
| 手机／平板应用接续至电脑 | [接续功能](https://consumer.huawei.com/cn/support/content/zh-cn16051202/)；[支持的应用与场景](https://consumer.huawei.com/cn/support/content/zh-cn16050156/) | 对应支持机型；设备均为 HarmonyOS 5 及以上；同一华为账号；开启 WLAN、蓝牙及接续；仅限支持的应用与场景 |
| 键鼠共享 | [操作与功能](https://consumer.huawei.com/cn/support/content/zh-cn16051201/)；[支持设备](https://consumer.huawei.com/cn/support/content/zh-cn16050145/) | 对应支持机型；设备均为 HarmonyOS 5.0.0.125 及以上；同一华为账号及功能开关；排除官方列明的不支持设备 |
| 平板作为电脑副屏 | [无线投屏至平板](https://consumer.huawei.com/cn/support/content/zh-cn16093701/)；[连接方式与限制](https://consumer.huawei.com/cn/support/content/zh-cn16049994/) | 对应支持机型；电脑和平板 HarmonyOS 6.1 及以上、同一华为账号并开启相关无线功能；Fold 特定形态另有 HarmonyOS 7.0 条件 |

这些条件来自 2026 年 10 月 19 日核查的官方页面，具体内容以各页面当前说明为准。生态体验以现有完整 PC 型号为入口，按对应文档组织手机、平板协同场景；未配置独立手机和平板产品规格库。WPS 接续限定云文档编辑页，小红书接续限定笔记发布页，不据此宣称任意应用、任意鸿蒙设备都能协同。动态价格、活动资格、库存和软件兼容结论仍需对应来源。

## 客户方案

- **客户洞察**：使用任务、预算与价值、决策阶段、顾虑与障碍、设备与体验环境五维逐条保留输入依据；没有提供的信息列为待确认。
- **四档报价**：标准方案、门店优惠、优惠组合、完整权益。录入具体 SKU、基础金额和来源，逐项填写权益金额、条件、有效期及叠加关系；使用 Decimal 计算并列出扣减过程。缺少来源或冲突条件时不补写成交价。最低金额仅比较已填报且可计算的方案。
- **180 秒演示**：六个时段安排需求确认、版本核对、实际任务、设备连接、携带体验及下一步；能引用的规格关联本次已验证事实。
- **1 / 3 / 7 天跟进**：依次补齐未确认项、回应顾虑和方案、征求继续联系意愿。输出为草稿，不自动联系客户。

报价模块按已录入的有来源金额进行算术示算；尚未接入真实订单、库存或门店促销系统。产品体验与跟进内容为导购可采用的计划和草稿，应用不会自动联系顾客或代发社交平台。

## 技术结构

| 文件 | 职责 |
|---|---|
| `app.py` | HTTP 接口、输入校验、缓存装载、运行保存、编辑复核、图片路由与导出 |
| `personalization.py` | 一句话归整、门店资料归一化、内容方向及重复表达提示 |
| `ima_client.py` | ima 只读检索、目录回退、型号绑定和媒体获取 |
| `public_evidence.py`、`data/` | 对照官方公开规格、原文及图片 SHA-256 |
| `ecosystem.py` | 六份官方生态原文的地址检查、完整型号与功能匹配 |
| `engine.py` | 三阶段模型调用、场景平台策略与生成核验 |
| `growth.py` | 五维输入依据、Decimal 报价、180 秒演示及跟进草稿 |
| `prompts/system_prompt.md` | 角色、场景、平台、知识、图片、生成、核验、合规与门店执行约束 |
| `static/` | 原生前端、门店工作台、真实结果视图；中文 STKAITI、英文 AnthropicSerifWebText |
| `examples/` | 已保存的真实图文运行结果与检查记录 |
| `tests/` | 输入与门店差异、来源覆盖、声明清理、报价边界等行为检查 |

### 主要接口

| 方法与路径 | 功能 |
|---|---|
| `POST /api/intake` | 归整一句话任务；返回可运行输入或必要补问 |
| `POST /api/generate` | 载入材料、三阶段模型处理、规则核查、客户方案与运行记录 |
| `POST /api/check` | 依据选定运行的事实检查已有文案；无依据时保留未核实状态 |
| `POST /api/revise` | 核验手工修改的标题与正文；通过后建立新运行并关联原运行 |
| `GET /api/runs/{run_id}` | 读取一次保存的实际结果 |
| `GET /api/runs/{run_id}/export?format=md\|json\|html\|zip` | 导出 Markdown、JSON、自包含 HTML 或图文 ZIP |
| `GET /api/catalog`、`GET /api/ecosystem` | 产品目录与适用生态来源 |
| `GET /api/examples`、`GET /api/status`、`GET /healthz` | 已保存案例、服务状态与健康检查 |

ZIP 包含 `图文.html`、`稿件.md` 和可用的本地图片；正文和图片来源保留在图文内。HTML 单文件导出内嵌可取得的图片。若某张图片缺少可取得的文件，导出保留来源链接，不能将这种结果标为图片已完整离线打包。HTML 和 ZIP 只交付通过核验的结果。

## 运行与部署

Python 3.12。

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# 在私有进程环境配置下表变量
python app.py
```

访问 `http://localhost:7860`。程序读取进程环境，复制 `.env.example` 不会自动加载配置。

| 变量 | 说明 |
|---|---|
| `IMA_OPENAPI_CLIENTID`、`IMA_OPENAPI_APIKEY` | 已加入知识库的账号凭证，仅保存在私密环境 |
| `MODEL_API_URL` | HTTPS 完整 `/chat/completions` 接口 |
| `MODEL_API_KEY`、`MODEL_NAME` | 模型凭证和服务方实际模型 ID |
| `MODEL_THINKING` | DeepSeek 思考模式，默认 `disabled`；按服务能力设为 `enabled` |
| `IMA_KB_NAME` | 默认指定共享库；可选 `谢家兴的知识库` 作为同内容来源 |
| `IMA_DATA_MODE` | 默认采用已核验缓存；`live` 尝试实时取材并在失败时使用可用缓存 |
| `MODEL_TIMEOUT_SECONDS` | 模型单次超时，默认 55 秒 |
| `PORT`、`ZHIHUA_RUNTIME_DIR` | 默认 7860、`/tmp/zhi-hua-runtime` |
| `MAX_CONCURRENT_RUNS`、`MAX_RUNS_PER_HOUR` | 默认并发 2、每来源每小时 24 次 |

当前配置示例使用魔搭推理服务模型 `deepseek-ai/DeepSeek-V4.1-Flash-1017`（DeepSeek-V4.1-Flash-1017）。模型 ID 来自服务端 `MODEL_NAME`，不在源码中固定返回结果。未配置服务时返回明确状态；实际使用的配置和调用结果应与部署验证记录一同核对。

```bash
docker build -t zhi-hua-agent .
docker run --rm -p 7860:7860 --env-file /private/path/agent.env zhi-hua-agent
python -m unittest discover -s tests -v
```

魔搭选择 Docker，应用端口 7860，健康检查 `/healthz`。凭证只放私密环境变量。应用供评委直接打开，生成接口不回传模型或 ima 凭证。

魔搭从固定的 GitHub 提交构建应用，完整源码以本 GitHub 仓库为准。[部署模板](deploy/modelscope.Dockerfile)可复制到创空间作为 `Dockerfile`；`SOURCE_REVISION` 默认固定为已公开的提交 `d4212b9c2026a6de6e0bd36fdd36bbd77ef5d0b3`，镜像标签同时记录该版本。构建时下载该提交的公开源码压缩包，安装声明的依赖，并以普通应用用户启动。更新时先提交源码，再将魔搭 Dockerfile 的 `SOURCE_REVISION` 改为目标提交的完整 SHA，重新构建部署；GitHub 后续提交不会自动改变这一固定版本。

## 验证方法

当前源码已完成 **44 项单元测试，全部通过**。另从全新的空运行目录加载仓库中的已保存案例，成功导出三份门店发布编辑版和一份生态接续结果：四份 HTML 均内嵌有效图片，四份 ZIP 的 HTML 与 Markdown 均引用包内相对图片路径，图片字节与静态原图一致。此次验证复用了既有真实运行成果，没有新增模型生成，也不依赖旧运行缓存。 三份历史案例另通过完整型号、原始来源 URL 和 SHA-256 精确匹配现有已核验素材，离线图文包分别恢复 3 / 3 / 1 张图片；历史运行原文未改动。

验证分别记录程序行为、真实模型结果和页面交付，不以旧版本测试总数代表新版通过情况：

1. 运行 `python -m unittest discover -s tests -v`，检查输入归整、门店上下文、来源覆盖、无依据声明的处理和报价条件边界。
2. 使用实际模型服务运行不同客群、至少两类场景与两种平台的内容；保存每次输入、`run_id`、时间、耗时、最终状态、事实原文、图片来源、核验与执行轨迹。失败和被阻止的结果按实际状态保留。
3. 固定同一完整机型与发布平台，执行三店比较，逐份检查顾客问题、开头、事实侧重和行动引导是否存在有意义差异。字符重合度只作为辅助观察。
4. 运行一个有完整官方条件的生态案例，例如 MateBook Pro 与手机备忘录接续，核对 `ecosystem_evidence` 中的来源及成稿限定。
5. 对成稿作手工编辑并复核，核对新 `run_id` 与 `parent_run_id`；比较页面、复制文本、MD、JSON、HTML 和 ZIP 中的最终稿。打开导出文件并实际检查图片与来源。
6. 在部署页面完成入口、必要补问、生成、三店比较、来源展开、编辑及下载操作，保存真实画面。性能数据只标注对应输入与运行，不能据单次运行推算门店效率或营销转化。

原文引用、独立语义核验与规则检查共同降低错误风险，仍需导购按具体 SKU、软件版本和现场环境确认再发布。屏幕或键盘规格本身不证明体验提升；产品图的型号与文件匹配也不构成性能测试。
